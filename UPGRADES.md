# Upgrades

## 4.2.0

- The build dependency ethos-zero moves from 10.0.0 (`4bf7`) to 19.2.0 (`5a5d`), and
  `src/generated/signal.rs` is regenerated by it from the unchanged `ethos/signal.ethos`; the
  build script still checks the committed file against that generator, which is now the only
  codec family in `Cargo.lock` (datom-codec 0.33.0, protos 0.33.0).
- Source API: the 46 scalar and container declarations that were type aliases are newtype structs
  with ordering derives where the scalar supports them, among them `TerminalName`, `TerminalRows`,
  `TerminalInputBytes`, `Terminal`, `Rows`, `InputBytes`, `Lease`, `Entries` and `SessionEntries`.
  A caller wraps where it built a scalar, as `Terminal(TerminalName("main".into()))`, and reads the
  scalar from `.0`.
- The archive and the Datom text are unchanged for the values tested: `tests/wire_equality.rs`
  builds the same data in the 4.1.0 types, taken verbatim from `src/generated/signal.rs` at 4.1.0
  as `tests/support/previous_410.rs`, and in the current types; the archives are byte equal for
  nine `Query`, eleven `Response` and two `TerminalDaemonConfiguration` samples, an old archive
  restores as the current value, and with `datom` the text is equal and reads back. These are
  representative values, not all values.

## 4.1.0

- The optional `datom` feature repins datom-codec 0.33.0 (eabead4) and protos
  0.33.0 (3c7ade3), up from 0.31.0. A consumer enabling `datom` repins both to
  those revisions and runs its tests.
- protos 0.33.0 reads a bare unbalanced guillemet inside a guillemet string, or
  a literal backslash before a guillemet, differently, and prints a balanced
  guillemet pair inside a string without an escape. A consumer holding datom text
  with either form re-reads it and updates the expectation.
- The generated contract is unchanged; the build script still checks it against
  `ethos/signal.ethos` with ethos-zero 10.0.0.
- A consumer building a `ReaderBudget` by its field replaces it with
  `ReaderBudget::try_from(n).unwrap()`; the field is private in protos 0.32.0 and later.
